# @suite/docs

The browsable site over the repository's documentation, on Astro and Starlight.
**`docs/` is the source of truth**; this app never holds a page of its own.
`scripts/sync-docs.mjs` mirrors `docs/` into `src/content/docs/` on every `dev`
and `build`, adding the frontmatter Starlight needs and rewriting links that
leave `docs/`. `internal/` is local-only and never synced.

## Layout

| Path | Purpose |
| --- | --- |
| `astro.config.mjs` | Starlight, the sidebar and the `llms.txt` plugin |
| `src/pages/index.astro` | The dashboard: hero, four section cards, a tab per section with a filter |
| `src/pages/[...slug].md.ts` | One page as Markdown, at the page's URL with `.md` appended |
| `src/content/docs/` | Generated by `scripts/sync-docs.mjs`; edit `docs/` instead |
| `src/integrations/` | The build step that copies a section's `.md` to `<folder>/index.md` |
| `src/styles/docs.css` | Starlight themed to the app's tokens |

The sidebar is configuration, not generated `meta.json`: `sidebar` in
`astro.config.mjs` autogenerates one group per section directory. The repository
README is served at `/overview`, because `/` is the dashboard.

## Run it

```sh
pnpm install
pnpm docs:site          # sync + astro dev, http://localhost:3001
```

## Build and serve

```sh
pnpm docs:site:build    # sync + astro build (output: apps/docs/dist)
pnpm docs:site:start    # astro preview on port 3001
```

Any static host works. `apps/docs/Dockerfile` builds the tree and serves it with
Caddy on port 3001 at `/srv/docs`, which is what `deploy/Caddyfile` expects for
`SUITE_DOCS_ROOT`.

## For agents

| Endpoint | Content |
| --- | --- |
| `/llms.txt` | the summary and links `starlight-llms-txt` generates |
| `/llms-full.txt` | every page, in full, in one file |
| `/llms-small.txt` | the same pages with asides and details removed |
| `/<slug>.md` | one page as Markdown, e.g. `/reference/architecture.md` |

Search is Pagefind, built by Starlight at the end of `astro build`, so there is no
search route or index to maintain.
