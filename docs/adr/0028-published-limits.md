# ADR-0028: The limits page is generated, and checked for drift

- **Status:** accepted
- **Date:** 2026-10-23
- **Related:** [ADR-0023](./0023-selection-projections.md), `docs/limits.md`, `apps/collab-server/src/limits.ts`

## Context

The quotas a single instance enforces already existed in one place — `limits.ts`, with an env name
per key and two default sets (self-host and hosted). What did not exist was a published page saying
what they are. The only prose that mentioned them was scattered across the runbook, and every number
in it was a copy.

A copied number is wrong the first time someone tunes a quota, and wrong invisibly: an operator reads
"100 share links", the code enforces 50, and the argument that follows is about who is lying rather
than about the limit. A9 asks for one page with workspace bytes, card count, attachment bytes per
workspace, shares per workspace, selection cards, open rooms, peers per room and restore targets —
eight facts from four different files, plus `compose.yaml`.

Two of those facts have no limit at all today: there is no card cap and no peers-per-room cap. A page
that quietly omits them implies the opposite, so the absence has to be stated, and stated in a way
that starts failing if someone adds a cap without updating it.

## Decision

1. **`docs/limits.md` is generated by `scripts/generate-limits.mjs`.** The script imports
   `limits.ts` (keys, env names, both default sets), `shares.ts` (`MAX_SELECTION_CARDS`),
   `projectionWorker.ts` (`DEFAULT_PROJECTION_ROOM_LIMIT`),
   `publishValidation.ts` (`DEFAULT_PUBLISH_LIMITS`) and reads `compose.yaml` for the store paths and
   the volume. Nothing on the page is typed by hand.
2. **`--check` is the gate.** `node scripts/generate-limits.mjs --check` renders the page in memory
   and fails when the committed file differs. It runs in the `quality` job beside `pnpm lint`, so a
   quota change without a regenerated page is a red build.
3. **The absence of a cap is data, not silence.** Cards per workspace and peers per room appear as
   explicit rows with "no cap" and the reason (bounded by document bytes; bounded by process memory).
   A future cap changes the row; the check then fails until the page is regenerated.
4. **Importing TypeScript from a script is done without a new dependency.** `scripts/ts-loader.mjs`
   registers a Node module hook that rewrites `./x.js` to `./x.ts` and transpiles with the TypeScript
   compiler the repo already installs. No `tsx`, no build step, no generated JSON checked in.
5. **Restore targets come from `compose.yaml`, not from a list.** The table is derived from the
   `SUITE_*_DB` values in the `app` service and the volume mounted at `/data`, and a store that is
   set to `:memory:` or not configured at all is marked as not surviving a container recreate. This
   is why the page showed three stores failing to survive before A1 and shows them fixed after it:
   the page follows the deployment rather than describing an intention.

## Consequences

- A quota change is a two-file change (the constant and the regenerated page), and forgetting the
  second is caught mechanically rather than in review.
- The page is only as good as its sources. A limit enforced somewhere the script does not read — a
  hard-coded `100` in an HTTP handler — stays invisible. The mitigation is the rule that limits live
  in `limits.ts`; a new one that does not is a review problem, not a generator problem.
- `compose.yaml` becomes a documented input to the docs, so a compose edit can fail the docs check.
  That is intended: it is the only way the restore-target table stays true.
- The generator runs on Node with the TypeScript compiler available, so it fails on a checkout with
  no `node_modules`. CI installs before running it, and the local gate does too.
- Regeneration is required after the A1 compose change lands, which the release notes call out; a
  stale page fails the check rather than shipping.

## Alternatives considered

- **A hand-written table in `docs/operations.md`** — the status quo, and the drift this ADR exists to
  prevent.
- **A `/limits` endpoint** — useful for machines, but it does not answer "what will happen to me" for
  a person reading the repository before deploying. A9 asks for one published page; an endpoint can
  come later without changing this decision.
- **Parse `limits.ts` with a regex** — survives without TypeScript, but silently misreads a refactor
  (a spread, a computed default). Importing the module fails loudly instead.
- **Add `tsx` as a dev dependency** — one more package to keep current for a script that runs twice
  a release. The loader is 40 lines and uses what is already installed.
