# @suite/docs

The browsable site over the repository's documentation. **`docs/` is the source
of truth**; this app never holds a page of its own. `scripts/sync-docs.mjs`
mirrors `docs/` into `content/docs/` on every `dev`/`build`, adding the
frontmatter Fumadocs needs and rewriting links that leave `docs/`. The site
publishes the dashboard and the four Diátaxis folders. `internal/` is local-only
and never synced.

## Dashboard

`/docs` is a four-card grid into the section indexes, followed by tabs for
Tutorials, How-to, Reference and Explanation. Each tab lists its pages newest
first and has a local filter. The section indexes in `docs/<section>/index.md`
are generated by `scripts/generate-doc-indexes.mjs`.

## Run it

```sh
pnpm install
pnpm docs:site          # sync + next dev, http://localhost:3001
```

## Build and serve

```sh
pnpm docs:site:build    # sync + next build (output: apps/docs/.next)
pnpm docs:site:start    # next start on port 3001
```

Any Node host works: run those two commands, or point a platform's build command
at `pnpm docs:site:build` and its start command at `pnpm docs:site:start`.

## For agents

| Endpoint | Content |
| --- | --- |
| `/llms.txt` | every page with its URL and description |
| `/llms-full.txt` | every page in full, in one file |
| `/docs/<slug>.md` | one page as Markdown (e.g. `/docs/reference/architecture.md`) |

Pages are read from disk at request time (`@fumadocs/local-md`), so a rebuilt
`content/docs/` is all a restart needs — no MDX compilation step.
